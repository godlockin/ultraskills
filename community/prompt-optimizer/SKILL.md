# Prompt Optimizer Skill

本技能提供一套**工业级**的prompt优化框架，融合认知科学与工程美学，帮助将自然语言需求转化为高效、精准、具备元认知能力的指令。

## 🎯 核心理念

### 四大基本特质

- **清晰性** (Clarity): 无歧义，易于理解
- **具体性** (Specificity): 明确细节，避免模糊
- **结构化** (Structure): 逻辑清晰，层次分明
- **可操作性** (Actionability): 指令明确，便于执行

### 三大进阶理念

- **元认知设计**: 不仅告诉AI"做什么"，更设计AI"如何思考"
- **防御性工程**: 零废话、防幻觉、兜底反问三件套
- **自适应交互**: 根据信息密度自动切换响应模式

> 📚 **进阶学习**: 查看 [高级技巧](./resources/advanced-techniques.md) 获取元认知架构、C.R.M.T.协议等高级内容

## 📋 优化流程

### 1. 分析原始Prompt

首先识别原始prompt的问题：

```markdown
## 原始Prompt分析清单
- [ ] 目标是否明确？
- [ ] 上下文是否充足？
- [ ] 输出格式是否指定？
- [ ] 约束条件是否清晰？
- [ ] 是否存在歧义表达？
- [ ] 是否缺少关键信息？
```

### 2. 应用CO-STAR框架

使用CO-STAR框架重构prompt：

| 元素 | 说明 | 示例 |
|------|------|------|
| **C**ontext (上下文) | 提供背景信息 | "你正在帮助一个初创公司..." |
| **O**bjective (目标) | 明确期望结果 | "生成一份商业计划书..." |
| **S**tyle (风格) | 指定写作风格 | "以专业但易懂的方式..." |
| **T**one (语气) | 设定情感基调 | "保持积极、鼓励的语气..." |
| **A**udience (受众) | 明确目标读者 | "面向非技术背景的投资者..." |
| **R**esponse (响应) | 指定输出格式 | "使用Markdown格式，包含..." |

### 3. 增强技巧

#### 3.1 角色设定 (Role Prompting)

```
你是一位拥有20年经验的[领域]专家...
```

#### 3.2 思维链 (Chain of Thought)

```
请一步步分析这个问题：
1. 首先...
2. 然后...
3. 最后...
```

#### 3.3 少样本学习 (Few-Shot Learning)

```
以下是一些示例：
示例1：[输入] -> [输出]
示例2：[输入] -> [输出]
现在处理：[新输入]
```

#### 3.4 输出约束

```
要求：
- 字数限制：500字以内
- 格式：Markdown
- 必须包含：标题、要点、总结
- 禁止：使用专业术语
```

## 📊 常见场景优化方案

### 场景一：代码生成

**优化前：** 写一个排序函数

**优化后：**

```markdown
# 任务
实现一个高效的排序函数

# 技术要求
- 语言：Python 3.10+
- 算法：快速排序
- 类型提示：必须包含完整的type hints

# 输出格式
- 函数代码
- 时间复杂度分析
- 使用示例
- 单元测试（至少3个测试用例）

# 代码风格
- 遵循PEP 8规范
- 包含docstring文档
- 变量命名清晰
```

### 场景二：文案撰写

**优化前：** 帮我写个产品介绍

**优化后：**

```markdown
# 角色
你是一位资深的科技产品文案策划专家

# 产品信息
- 产品名称：[名称]
- 核心功能：[功能列表]
- 目标用户：[用户画像]
- 竞争优势：[差异化卖点]

# 任务
撰写一篇产品介绍文案

# 输出要求
- 长度：300-500字
- 风格：专业而不失温度
- 结构：
  1. 吸引眼球的开头
  2. 痛点共鸣
  3. 解决方案展示
  4. 核心功能亮点（3个）
  5. 行动号召

# 禁止事项
- 不使用夸张的营销术语
- 不做虚假承诺
```

### 场景三：问题分析

**优化前：** 分析这个问题

**优化后：**

```markdown
# 角色
你是一位专业的问题分析顾问

# 问题描述
[详细描述问题]

# 分析框架
请使用以下步骤进行分析：
1. **问题定义**：准确界定问题边界
2. **根因分析**：使用5 Whys或鱼骨图方法
3. **影响评估**：分析问题的影响范围和程度
4. **解决方案**：提供至少3个可行方案
5. **建议行动**：给出优先级排序的行动建议

# 输出格式
Markdown格式，每个步骤使用二级标题
```

## ✅ 优化检查清单

完成优化后，使用此清单验证：

```markdown
## Prompt质量检查

### 完整性
- [ ] 是否包含足够的上下文？
- [ ] 目标是否明确且可衡量？
- [ ] 是否指定了输出格式？

### 清晰度
- [ ] 语言是否简洁明了？
- [ ] 是否消除了歧义表达？
- [ ] 逻辑顺序是否合理？

### 有效性
- [ ] 约束条件是否合理？
- [ ] 是否提供了必要的示例？
- [ ] 是否考虑了边界情况？

### 可优化空间
- [ ] 是否可以添加角色设定？
- [ ] 是否可以使用思维链？
- [ ] 是否可以添加评估标准？
```

## 🛠 使用方法

当需要优化prompt时：

1. **获取原始prompt**：用户提供需要优化的prompt
2. **分析问题**：使用分析清单识别问题
3. **应用框架**：使用CO-STAR或其他适用框架
4. **增强优化**：添加角色、思维链等增强技巧
5. **输出结果**：提供优化后的prompt并解释改进点
6. **验证检查**：使用 [PEER评分标准](./resources/evaluation-rubric.md) 验证质量

## 🛡️ 防御性设计三件套

### 1. 零废话协议

```markdown
## 输出规范
- 禁止输出"好的，我来为您..."等客套话
- 禁止输出"希望对您有帮助"等结尾语
- 直接进入正题，开门见山
```

### 2. 防幻觉指令

```markdown
## 知识边界
- 如果不确定答案，必须声明"我不确定"
- 禁止编造不存在的引用、数据、事实
- 推测性内容必须标注
```

### 3. 兜底反问机制

```markdown
## 信息不足时
当输入信息不足以完成任务时：
1. 识别具体缺失的信息点
2. 结构化地向用户提出追问
3. 不要基于假设强行输出
```
