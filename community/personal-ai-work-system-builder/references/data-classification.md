# 数据分级与安全

> 先分级,再决定能否上传、能否出境、需否脱敏。分级发生在**连接任何 AI 之前**,不是出问题之后。
>
> **法源**:分级分类义务见《数据安全法》第 21 条;个人信息定义与去标识化见 GB/T 35273-2020 §3.1、§3.14。

## 5 级分级判据表

| 级别 | 典型内容 | 可走公网 AI? | 可出境? | 必须脱敏字段 | 建议留存 |
|---|---|---|---|---|---|
| **L0 公开** | 官网文案、公开课程大纲、行业新闻 | ✅ 是 | ✅ 是 | 无 | 不限 |
| **L1 内部** | 内部 SOP、非敏感会议纪要、产品规划草稿 | ✅ 是(建议企业版) | ⚠️ 评估 | 内部人员姓名可保留 | 按项目周期 |
| **L2 机密** | 定价策略、未发布产品、供应商合同条款 | ⚠️ 仅企业版/私有部署 | ❌ 否 | 交易对手名称、金额 | 3 年 |
| **L3 客户个人信息** | 姓名、手机、身份证、地址、聊天记录、健康信息 | ❌ 否(必须脱敏后) | ❌ 否 | 全部直接标识符 + 可组合识别字段 | 依业务必要最短 |
| **L4 资金/审批** | 银行账号、支付凭证、退款记录、审批链 | ❌ 否 | ❌ 否 | 账号、金额、审批人 | ≥6 个月(网络安全法 Art.21) |

### 判定顺序

1. 数据里有**任何自然人可识别信息**吗?→ 有则至少 L3
2. 涉及**钱的流向或审批权**吗?→ 是则 L4
3. 泄露会造成**竞争损失**吗?→ 是则 L2
4. 只对内有意义?→ L1
5. 已公开?→ L0

**同一份文件混合多级时,按最高级处理。**

## 跨境数据红绿灯 (PIPL 第 38-39 条)

个人信息出境需满足以下之一:**通过安监部门安全评估 / 经认证 / 订立标准合同 / 其他法定条件**。个人用户搭系统时通常都不满足,因此:

| 分级 | 境内 AI (通义/文心/豆包/智谱/私有部署) | 境外 AI (Claude/GPT/Gemini) |
|---|---|---|
| L0 公开 | ✅ | ✅ |
| L1 内部 | ✅ | ⚠️ 需内部批准 |
| L2 机密 | ⚠️ 企业版 | ❌ |
| L3 客户个人信息 | ⚠️ 脱敏后 + 已获同意 | ❌ **禁止** |
| L4 资金/审批 | ❌ | ❌ **禁止** |

**实操规则**:访谈和设计阶段只用**系统名称、字段结构、脱敏样例**;真实 L3/L4 数据的处理必须在境内系统内完成,AI 只接收聚合后的结果(如"本周 5 个客户推进"而非客户名单)。

### 出境前评估清单 (若确需)

- [ ] 已识别出境的具体字段清单
- [ ] 已取得个人单独同意(PIPL Art.39,不能用概括性隐私政策)
- [ ] 已告知境外接收方名称、联系方式、处理目的、方式、种类
- [ ] 已完成个人信息保护影响评估(PIA)并留档 3 年
- [ ] 已确认符合安全评估/认证/标准合同之一

**任一项未满足 → 不出境。**

## 对外消息 3 项必填 (PIPL Art.13-14 / 广告法 Art.43 / GDPR Art.6 + ePrivacy Art.13)

自动化**批量**向客户/用户发送消息前,必须全部具备:

| # | 必填项 | 证据形式 |
|---|---|---|
| 1 | **收件人同意凭证** | 同意时间 + 同意场景 + 同意范围(不能用"购买过就默认同意营销") |
| 2 | **退订入口** | 每条消息含可用退订方式;退订后 48h 内生效并记录 |
| 3 | **频次与时间窗** | 单人单周上限 + 免打扰时段(建议 22:00-08:00 不发) |

三项缺一 → 该自动化状态最高只能标 **半自动**(人工逐条确认后发送)。

> 中国境内商业营销另受《广告法》第 43 条(未经同意不得向住宅/交通工具/电子邮箱发送广告)与《民法典》第 1033 条(私人生活安宁)约束。涉欧盟用户时,电子营销受 ePrivacy Directive Art.13 约束,单靠 GDPR Art.6 正当利益通常不足。

## 财务动作闸门

| 动作 | 门槛 | 留存 |
|---|---|---|
| 付款 / 退款 | **任何金额**均需一次性确认码;金额 ≥ 用户自定阈值 → **双人审批** | 审计日志 ≥6 个月 |
| 权限变更 | 一律人审,不可自动 | ≥6 个月 |
| 删除数据 | 一律人审 + 可恢复窗口(建议 7 天软删除) | ≥6 个月 |

**阈值硬下限**:双签阈值**不得高于用户本人的单笔审批权限**。不存在"无需确认码的自动付款"。

法源:日志留存见《网络安全法》第 21 条。

## 密钥卫生 (Secret Hygiene)

**绝对禁止**把以下内容写入 `SYSTEM-BLUEPRINT.md` / `SYSTEM-STATE.md` / `AUTOMATION-REGISTRY.md` / SOP / 聊天记录:

* API key / token / secret
* 密码 / cookie / session
* 私钥 / 证书

**正确做法**:

```markdown
<!-- ✅ 连接层文档里这样写 -->
| 系统 | 认证方式 | 凭证位置 |
|---|---|---|
| 企业微信 | corp_secret | ${WECOM_SECRET} → 见 .env |
| 神策 | API token | ${SENSORS_TOKEN} → 系统密钥管理器 |
```

* 真实值放 `.env`(且 `.env` 加入 `.gitignore`)或 macOS Keychain / 1Password / 云厂商 KMS
* 蓝图和登记表只写变量名与存放位置
* 已经误写入的,视为**已泄露**:立即轮换密钥,再清理文件历史

## AI 决策责任声明

本 skill 输出的自动化建议、优先级排序、成熟度判定均为**辅助参考**,不构成合规意见或专业建议。上线任何自动化前:

* 由**用户本人**确认是否符合所在组织的制度与适用法规
* 涉及个人信息处理的,建议完成 PIA(个人信息保护影响评估)
* `AUTOMATION-REGISTRY.md` 每行须记录 **AI 建议 / 人工拍板人 / 是否可回滚** 三栏
* AI 的判断可被用户覆写,覆写理由记入执行记录

法规依据:内容生产者责任见《生成式人工智能服务管理暂行办法》第 9 条;使用者输入信息的留存限制见同办法第 11 条;个人信息处理规则见《个人信息保护法》;数据分级义务见《数据安全法》第 21 条;日志留存见《网络安全法》第 21 条。涉欧盟业务另参 GDPR 与 ePrivacy Directive。
