# 搭建、验证与迭代

## 从蓝图进入搭建

先确认第一条闭环、权威数据源、人工确认点、输出和保存位置。只向用户索取当前闭环必需的资料或权限，不一次性要求所有系统资料。

## 能力边界表

| 能力/系统 | 当前状态 | 能执行什么 | 需要什么 | 人工确认 | 最后验证 |
|---|---|---|---|---|---|

状态只使用：已连接可执行、已连接只读、可生成草稿、需登录、需授权、需插件/API、规划中、不可用。

## 搭建顺序

1. 复制系统档案模板并填入用户信息；
2. 建立项目与权威资料入口；
3. 固定第一条流程的输入、判断、输出和归档；
4. 先用真实或脱敏数据手动跑通；
5. 接入可用工具，保留人审与异常停止；
6. 再次端到端运行并记录指标；
7. 更新状态、资产和自动化登记；
8. 只在验证通过后升级自动化状态。

## 一小时快速成果 vs 第一条闭环

> **这两件事必须严格区分,不能互相顶替。**

### A. 一小时快速成果(蓝图类,允许纯文档)

即使外部连接暂时不可用,也应从下列成果中完成至少一项:

- 可直接复制使用的统一任务入口提示词
- 一条流程的标准输入表与验收清单
- 项目知识库目录及资料迁移清单
- 一份基于用户真实案例的 SOP
- 一个带真实数据口径的看板原型
- 一个能处理代表性输入的 Skill 或任务模板

**交付这些时必须同时说明:"这是快速成果,第一条闭环尚未跑通。"**

### B. 第一条闭环(必须有执行证据,不接受纯文档)

只有**全部**满足才算跑通:

| 要求 | 证据 |
|---|---|
| 真实或脱敏代表性输入 | 输入版本号 / 文件名 / 日期 |
| AI 实际处理完成 | 输出内容本身 |
| 必要人审已发生 | 确认记录(谁、何时、确认了什么) |
| 真实交付物产出 | 输出位置(文件路径 / 表格链接 / 消息 ID) |
| 结果已归档 | 写入 `04_执行记录与案例.md` |
| 耗时已记录 | 数字 + 单位 |
| 异常路径已知 | 至少测过一种失败情形 |

**"我给你写了流程说明"不是闭环。"我设计了自动化方案"不是闭环。只有真实输入走完并留下记录才是。**

## 运行后学习

每次运行写入：运行日期、触发人、输入版本、输出位置、耗时、错误、人工修正、是否通过、指标变化。若同一修正出现两次，优先把规则写回SOP或Skill；若同一异常出现三次，暂停自动执行并重新设计。

## 可迁移性

将内容分成两类：

- **稳定层**：业务规则、数据口径、判断标准、模板、知识与验收标准；
- **连接层**：具体模型、App、API、浏览器步骤和账号权限。

更换工具时只重做连接层。若业务规则写死在某个工具中，应同时保存一份平台无关版本。
