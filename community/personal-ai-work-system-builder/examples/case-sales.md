# 案例:销售/客户运营

## 用户画像

* **岗位**:B2B 销售经理,管 30 个活跃客户
* **行业**:企业 SaaS
* **工具现状**:企业微信 + 飞书表格 + 个人备忘录,客户信息散落 3 处
* **核心痛点**:周会前手动汇总客户跟进状态,1.5 小时起步

## 第一次访谈 (节选)

> **Q1**:你的岗位、行业和主要职责?
> A:B2B 销售经理,管 30 个客户。
>
> **Q2**:30 天最希望 AI 帮拿到的 3 个结果?
> A:(1) 周会自动生成客户跟进看板 (2) 续约提醒不漏 (3) 报价单模板自动填充。
>
> **Q3**:每周重复的最耗时 3-5 项?
> A:周会汇总、报价单、客户生日/续约提醒、合同初稿、月底业绩统计。
>
> **Q6**:本周最想跑通的一条?
> A:**周会自动生成客户跟进看板** — 这个每周都做。

## 诊断卡

```
你的系统定位:为 B2B 销售搭建"客户跟进可追溯 + 周会一键就绪"的工作系统
当前成熟度:L2 (已有飞书表格模板,但每次手动复制)
最大断点:客户信息散落企业微信/表格/备忘录,口径不统一
第一条闭环:周日 AI 自动生成"本周客户跟进看板"
最小工具组合:Claude (主控) + 飞书多维表格 (业务系统)
本周先交付:飞书表格模板 + 周报自动生成 SOP
```

## 步骤压缩图

| 流程 | 现状人工步骤 | 目标人工步骤 | 步骤去向 | 验证指标 |
|---|---:|---:|---|---|
| 周会跟进汇总 | 6 | 1 | 5 步自动 (导出 → 境内模型脱敏解析 → 填表格 → 生成聚合摘要 → 推送) | 90min → 5min |
| 续约提醒 | 3 | 1 | 2 步自动 (提前 30 天生成待发清单 → 人工确认后发送) | 漏提醒 0 次 |
| 报价单生成 | 4 | 1 | 3 步自动 (选模板 → 填字段 → 导出 PDF) | 20min → 2min |

> **为什么续约提醒不是 0 步**:批量客户触达属高风险动作,受 PIPL 告知同意约束,必须保留人工确认。见下方合规检查。

## 四层架构 (本案例)

```
统一入口:Claude Chat (周日触发"生成本周跟进看板")
  ↓
AI 角色:
  - 境内模型/私有部署:解析企微原始对话 (含客户可识别信息 = L3)
  - Claude 主控:仅接收脱敏聚合结果,生成摘要与建议
  ↓
业务系统:企业微信 (客户对话源) + 飞书多维表格 (看板) + 邮箱 (报价单)
  ↓
资产沉淀:
  ├── 00_项目说明.md
  ├── 01_客户档案与口径.md
  ├── 02_SOP_周会汇总.md
  ├── 03_话术与模板/报价单.md
  └── 04_执行记录_2026W34.md
```

> **数据分级设计**:企微原始对话含客户名 = **L3 客户个人信息**,按 [跨境红绿灯](../references/data-classification.md) 禁止走境外 AI。因此拆两段:境内模型做脱敏解析(客户名 → 客户 ID),Claude 只看聚合摘要("本周 5 个客户推进")。

## 第一个闭环详细设计

**触发方式**:每周日 20:00 自动 (cron)

**输入**:
* 企业微信本周对话导出 (CSV,**导出后先经境内脱敏:客户名 → C001 形式的 ID**)
* 飞书客户表格当前状态 (仅客户 ID + 状态字段)

**AI 执行**:
1. 境内模型解析对话提取客户 ID + 状态关键词 (签约/续约/异议/待跟进)
2. 与飞书表格合并,标记状态变化
3. Claude 基于**聚合结果**生成摘要:"本周 5 个客户推进,2 个续约待签,1 个异议待处理"

**人工确认**:摘要出现异常 (连续 3 周无更新) 时人工介入

**外部动作**:自动推送摘要到企业微信"销售管理群"(内部群,非客户触达)

**输出**:飞书表格 + 群消息 + `04_执行记录.md`

**成功指标**:周会汇总时间从 90min 降至 ≤5min,漏跟进率 0

## 合规检查

| 检查项 | 本案例的处理 |
|---|---|
| **数据分级** | 企微原始对话 = L3(含客户可识别信息);聚合摘要 = L1 内部 |
| **出境判定** | L3 不出境 — 境内模型/私有部署做解析;Claude 只接收 L1 聚合结果 |
| **客户触达同意** | 续约提醒**不自动发送**。系统生成待发清单,销售确认收件人已在同意范围内后手动发送 |
| **退订入口** | 提醒消息模板含退订说明;退订记录回写飞书表格 |
| **频次约束** | 单客户单月最多 1 次续约提醒;22:00-08:00 不发送 |
| **人审节点** | 所有对客户的消息发送前人工确认;摘要异常时人工介入 |
| **自动化状态** | 周会汇总 = 半自动;续约提醒 = 半自动(不是全自动) |
| **凭证管理** | 企微 corp_secret 存 `.env`,蓝图只写 `${WECOM_SECRET}` |

### 授权门实例

续约提醒确认时,系统输出:

```
RISK-ALERT
动作:发送续约提醒
对象:5 位客户(C003, C007, C012, C019, C024)
影响:对外消息,不可撤回;已核对均在营销同意范围内
回滚:无法撤回已发送消息,可后续致歉说明
确认请回复:GO-YES-W34-01
```

销售回复 `GO-YES-W34-01` 后才发送。回复"可以""发吧"均**不生效**。

## 复盘 (4 周后)

* 续约提醒改半自动后,实际漏提醒从季度 2-3 次降至 0,人工确认成本约 2min/周
* 周会摘要被销售总监采纳作为模板
* 境内解析 + 境外摘要的两段式设计增加了一次数据流转,但避免了 L3 出境风险
* 新需求:把"客户异议库"也自动化 — 进入第二条闭环

## 不做的事

* ❌ 不搭独立 Web 看板 (飞书表格足够)
* ❌ 不引入 CRM 系统 (30 个客户用不到)
* ❌ 不写独立 Skill (SOP 已沉淀到飞书文档)
* ❌ **不把客户原始对话发给境外 AI** (L3 数据不出境)
* ❌ **不让 AI 直接发送客户消息** (批量触达必须人工确认)
