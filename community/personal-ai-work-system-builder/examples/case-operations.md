# 案例:运营/数据分析

## 用户画像

* **岗位**:增长运营,管 5 个渠道投放
* **行业**:消费 App
* **工具现状**:神策 + 飞书表格 + 微信公众号 + 邮件 + 内部 BI,数据散落 5 处
* **核心痛点**:每周渠道数据汇总 4 小时,月底 ROI 复盘仍靠 Excel 拼

## 第一个闭环详细设计

**触发方式**:每日 09:00 cron

**输入**:
* 神策 API 昨日渠道数据 — **仅聚合指标**(曝光/点击/转化/成本),不拉取 device_id、手机号、用户级明细
* 历史 7 天同渠道数据 (用于对比趋势)

**AI 执行**:
1. 拉取 5 个渠道昨日关键指标 (CTR/CAC/ROI/转化率)
2. 与 7 天均值对比,标记异常 (>±20%)
3. 生成 200 字摘要:"今日 A 渠道 CTR 上升 15% (源自新素材),B 渠道 ROI 下降 22% (建议排查)"
4. 写入飞书表格 + 推送运营群

**人工确认**:异常告警需运营确认原因

**外部动作**:自动推送飞书群消息(内部群,非对外触达)

**输出**:飞书表格 + 群消息 + `04_日报_YYYY-MM-DD.md`

**成功指标**:日报时间从 90min 降至 0,异常发现到响应从 T+1 降至 T+0

## 合规检查

| 检查项 | 本案例的处理 |
|---|---|
| **数据分级** | 聚合渠道指标 = L1 内部;用户级明细(device_id/手机号)= L3,**本闭环不拉取** |
| **出境判定** | 只有 L1 聚合指标进 Claude;若需下钻到用户级,必须改用境内模型 |
| **对外动作** | 仅推送内部运营群;不涉及客户触达 |
| **人审节点** | 预算调整、素材修改均人工;AI 只出建议 |
| **自动化状态** | 日报 = 全自动(内部只读+内部推送,低风险);预算调整 = 手动 |
| **凭证管理** | 神策 API token 存 `.env`,蓝图写 `${SENSORS_TOKEN}` |

> **为什么日报可以标"全自动"**:它只读内部聚合数据、只写内部表格、只推内部群,不触碰个人信息也不产生不可逆外部动作。这与"退款/客户触达"类高风险动作有本质区别。即便如此仍需每 7 天验证一次。

## 复盘 (8 周后)

* 日报 100% 自动出,运营从未加班做日报
* ROI 异常告警从"周发现"提速到"日发现",挽回 3 次大额浪费(估计节省 ¥12 万)
* **关键学习**:神策数据口径必须固化在 `01_数据口径.md`,否则 AI 解读漂移
* **关键学习**:一开始想拉用户级明细做精细分析,发现属 L3 需出境评估,改为聚合指标后同样够用

## 不做的事

* ❌ 不让 AI 自动调整投放预算(必须人审)
* ❌ 不让 AI 自动改素材(创意必须人工)
* ❌ 不引入额外 BI 工具(神策 + 飞书已足够)
* ❌ **不拉取用户级明细数据**(聚合指标已满足需求,避免 L3 出境)
