# 案镜 (cn-anmirror) — 案件分诊镜

> **镜鉴 suite · 第一镜**：在所有法律工作开始前，先看清案件的全貌。

## 与其他"案"类 skill 的本质区别

| 维度 | 普通 fact extraction | 案镜 |
|---|---|---|
| 输出深度 | 仅事实清单 | 事实 + 关系 + 复杂度 + 路径 |
| 法律关系识别 | 弱 / 单一 | **多关系并行识别**（按概率排序）|
| 复杂度评估 | 无 | **5 级分类** + 影响因子分析 |
| 下游衔接 | 无 | **自动推荐** skill 路径 |
| MCP 数据需求 | 无标注 | **显式标注** 哪些环节需要 yuandian/法宝/威科 |

## 何时触发

- 用户丢来一段案件材料，要求"分析"、"梳理"、"评估"
- 律师接到新咨询 / 新案，需要快速分诊
- 任何后续 skill（`limirror` / `famirror` / 上游 plugins）开始前的**事实地基**构建

## 何时不触发

- 纯法理 / 政策讨论（无具体事实）
- 已结构化的事实清单（直接处理）
- 仅需单一事实点 / 数据点查询

## 工作流：7 步分诊法

### 步骤 1：当事人全识别

识别**所有**参与法律关系的当事人，按主体类型 + 在关系中的角色双维度分类：

| 维度 | 分类 |
|---|---|
| 主体类型 | 自然人 / 法人 / 非法人组织 / 不特定主体 / 监管机构 |
| 角色 | 原告 / 被告 / 第三人 / 申请人 / 被申请人 / 关系人 / 见证人 |

**强制还原**：聊天记录 / 口头协议中的代词（"我"/"他"/"对方"）必须还原为具体主体或标注「主体不明」。

### 步骤 2：行为时间线（带证据链）

按时间先后列出所有具有法律意义的行为，**每条标注证据来源**：

```
[timestamp/date] 主体 → 行为 + 对象 + 结果（带证据来源标识）
```

证据来源标识：
- `[原件]` 原始文件 / 合同文本
- `[电子]` 微信 / 邮件 / 短信
- `[录音]` 录音录像
- `[证人]` 证人证言
- `[缺失]` 事实存在但缺证据
- `[待核]` 当事人陈述待对方确认

⚠️ **关键原则**：未注明日期 = 「时间不明」,**不虚构日期**。

### 步骤 3：标的三层识别

按主从标的**三层**识别：

| 层级 | 含义 |
|---|---|
| 主标的 | 法律关系核心客体（合同金额、侵权损害物） |
| 从标的 | 衍生客体（利息、违约金、损害赔偿） |
| 隐藏标的 | 隐含利益（商誉、商业机会、信赖利益） |

### 步骤 4：法律关系并行识别（概率排序）

识别**所有可能**涉及的法律关系，按概率排序：

| 概率 | 标识 | 应对 |
|---|---|---|
| 高 (>70%) | 🔴 | 必查 |
| 中 (30-70%) | 🟡 | 需补证 |
| 低 (<30%) | 🟢 | 仅作防御 |

每个关系标注**识别信号词**（合同关系：合同/协议/约定/违约；侵权关系：损害/过错/因果关系...）

**重要**：同一案件常涉及 2-4 种法律关系（如"合同 + 侵权"选择之诉、"劳动 + 社保"复合请求）。

### 步骤 5：复杂度 5 级评估

按 5 个维度评估，每维 1-5 分，加权平均：

| 维度 | 权重 | 评分依据 |
|---|---|---|
| 事实清晰度 | 0.20 | 证据完整度、矛盾程度 |
| 法律关系数 | 0.20 | 涉及关系种类数 |
| 法条新颖度 | 0.15 | 是否涉及新法 / 司法解释 |
| 程序复杂度 | 0.20 | 管辖、审级、是否涉外 |
| 标的金额 / 影响 | 0.25 | 金额大小、社会影响 |

**复杂度分档**：
- **1-1.5**: 极简 — 标准合同审、单一违约
- **1.5-2.5**: 简单 — 单一法律关系，事实清楚
- **2.5-3.5**: 中等 — 涉及 2-3 种关系或部分事实争议
- **3.5-4.5**: 复杂 — 多种关系 + 程序问题 + 大标的
- **4.5-5.0**: 极复杂 — 涉外 / 新型 / 群体性 / 重大公共利益

### 步骤 6：MCP 数据源需求标注

对每个可能涉及的事实 / 法条 / 案例，标注**所需数据源**：

| 数据源类型 | 适用场景 | 推荐 MCP |
|---|---|---|
| 法条 / 法规 现行性 | 引法条时 | 北大法宝 / 威科先行 / 元典 |
| 类案检索 | 法律关系初判后 | 元典 / 聚法案例 |
| 司法解释配套 | 法条新颖度高时 | 北大法宝 |
| 指导性案例 | 复杂案件 | 最高法官网 |
| 行业规范 / 习惯 | 行业案件 | 行业专门数据库 |

⚠️ **未连接 MCP 时**：明示标注「[待权威数据库核验]」，**不臆测**。

### 步骤 7：下游路径推荐

基于复杂度与法律关系，推荐下游 skill 路径：

| 场景 | 推荐路径 |
|---|---|
| 极简 + 单一关系 | 直接进入 `limirror` |
| 简单 + 1-2 关系 | `limirror` → `famirror` |
| 中等 + 多关系 | `limirror` + 多领域 plugin (commercial-legal / employment-legal 等) |
| 复杂 | `limirror` + 多 plugin + 类案检索 + 专家协同 |
| 极复杂 | `鉴枢 (cn-jianshu)` 编排模式 |

## 质量自检清单（输出前必走）

- [ ] 所有代词已还原或标注「主体不明」
- [ ] 所有时间点有日期或「时间不明」,**不虚构**
- [ ] 法律关系识别覆盖 ≥2 种可能性（不只挑最显眼的）
- [ ] 复杂度评分五维度齐全,综合分加权正确
- [ ] 证据缺口**显式列出** + 影响标注
- [ ] MCP 数据需求按场景分类,**未连接时不臆测**
- [ ] 下游路径含主线 + 旁路 + 工作量评估

## 与镜鉴 suite 内部衔接

| 下游 | 关系 |
|---|---|
| `limirror` (理镜) | 主线第一步 — 把事实要素转化为要件推导 |
| `famirror` (法镜) | 并行 — 验证所引用法条的现行有效性 |
| `鉴枢` (cn-jianshu) | 复杂案件 — 编排所有镜 + CSlawyer1985 plugins |

## 与上游 CSlawyer1985 插件衔接

`案镜` 是**前置 skill** —— 在调用 `commercial-legal` / `litigation-legal` 等 plugin 之前先跑 `案镜`,为它们提供结构化的事实地基。

| Plugin | 衔接点 |
|---|---|
| commercial-legal | 案镜输出"合同关系 + 违约事实"→ plugin 起草合同法律意见 |
| litigation-legal | 案镜输出"案件事实 + 法律关系 + 复杂度"→ plugin 设计诉讼策略 |
| employment-legal | 案镜输出"劳动关系事实"→ plugin 评估劳动法风险 |
| privacy-legal | 案镜输出"个人信息处理事实"→ plugin 评估 PIPL 合规 |
