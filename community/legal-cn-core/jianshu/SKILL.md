# 鉴枢 (cn-jianshu) — 镜鉴中枢

> **镜鉴 suite · 第四镜（编排层）**：让 3 面镜子 + 13 个上游 plugin 协同工作。

## 角色定位

```
                    ┌─────────────────┐
                    │   鉴枢 (本)    │
                    │   编排入口      │
                    └────────┬────────┘
                             │
            ┌────────────────┼────────────────┐
            │                │                │
       ┌────▼─────┐    ┌────▼─────┐    ┌────▼─────┐
       │  案镜    │    │  理镜    │    │  法镜    │
       │ 事实地基 │    │ 要件推理 │    │ 规范审查 │
       └────┬─────┘    └────┬─────┘    └────┬─────┘
            │                │                │
            └────────────────┴────────────────┘
                             │
            ┌────────────────┴────────────────┐
            │   CSlawyer1985 13 plugins       │
            │  commercial / corporate / ...  │
            │  privacy / employment / ...    │
            │  litigation / criminal / ...   │
            └─────────────────────────────────┘
```

## 何时触发

- 用户提交**完整法律任务**,需多步协调
- 案镜输出"极复杂"分档（4.5-5.0 分）时**自动**接管
- 用户明确要求"全套"、"综合"、"流程化"法律服务

## 何时不触发

- 单一原子任务 → 直接调对应镜
- 纯信息查询（"民法典第 X 条是什么"）→ 直接调法镜
- 非法律领域问题

## 工作流：5 阶段编排

### 阶段 0：任务意图识别

判断用户任务的真实意图,选择编排模板：

| 模板 | 触发信号词 | 涉及镜 + plugins |
|---|---|---|
| **合同审阅** | "审合同"、"起草合同"、"合同条款"、"违约" | 案镜 → 理镜 → commercial-legal |
| **诉讼策略** | "起诉"、"应诉"、"答辩"、"证据"、"管辖" | 案镜 → 理镜 → litigation-legal |
| **合规审查** | "合规"、"PIPL"、"个保法"、"数据" | 案镜 → 法镜 → privacy-legal / regulatory-legal |
| **劳动争议** | "劳动"、"开除"、"工伤"、"工资" | 案镜 → 理镜 → employment-legal |
| **公司治理** | "股权"、"股东会"、"增资"、"并购" | 案镜 → 理镜 → corporate-legal |
| **知识产权** | "商标"、"专利"、"侵权"、"版权" | 案镜 → 理镜 → ip-legal |
| **AI 合规** | "算法"、"AI 备案"、"生成式" | 案镜 → 法镜 → ai-governance-legal |
| **刑事辩护** | "刑事"、"犯罪"、"辩护"、"会见" | 案镜 → 理镜 → criminal-legal |
| **产品上市** | "产品"、"广告"、"营销" | 案镜 → 法镜 → product-legal |
| **法务咨询** | 模糊 / 综合 | 案镜 → 全路径 → 专家协同 |

### 阶段 1：案镜初始化

**强制前置**：所有任务先经案镜分诊。

输出关键参数：
- 法律关系列表 + 概率
- 复杂度分档
- MCP 数据需求

### 阶段 2：路由决策矩阵

根据案镜输出,选择编排路径：

| 复杂度 | 关系数 | 编排路径 |
|---|---|---|
| 极简 (1-1.5) | 1 | 案镜 → 理镜 |
| 简单 (1.5-2.5) | 1-2 | 案镜 → 理镜 → 法镜 |
| 中等 (2.5-3.5) | 2-3 | 案镜 → 理镜 → 法镜 → 1-2 plugins |
| 复杂 (3.5-4.5) | 3+ | 案镜 → 法镜 → 多 plugin → 类案检索 → 协同 |
| 极复杂 (4.5-5.0) | 多 | 全套镜 + 多 plugin + 多专家协同 |

### 阶段 3：plugin 调度

按模板调用对应 CSlawyer1985 plugin：

| plugin 路径 | 调用命令（示意） |
|---|---|
| `external/claude-for-legal-ZH/commercial-legal/` | 加载商业合同 plugin |
| `external/claude-for-legal-ZH/litigation-legal/` | 加载诉讼 plugin |
| `external/claude-for-legal-ZH/privacy-legal/` | 加载隐私合规 plugin |
| `external/claude-for-legal-ZH/employment-legal/` | 加载劳动 plugin |
| `external/claude-for-legal-ZH/corporate-legal/` | 加载公司 plugin |
| `external/claude-for-legal-ZH/ip-legal/` | 加载知产 plugin |
| `external/claude-for-legal-ZH/ai-governance-legal/` | 加载 AI 合规 plugin |
| `external/claude-for-legal-ZH/criminal-legal/` | 加载刑事 plugin |
| `external/claude-for-legal-ZH/regulatory-legal/` | 加载监管 plugin |
| `external/claude-for-legal-ZH/product-legal/` | 加载产品 plugin |

⚠️ **plugin 调用约束**：
- 仅在用户需求**确实涉及**对应领域时调用
- 不要"全套调用"以避免 token 浪费
- plugin 输出的实务工作（合同起草 / 诉状撰写 / 合规报告）**优先于**镜鉴 suite 的结构化输出

### 阶段 4：MCP 数据流编排

按任务需要,**并行调度** MCP 数据源：

| 数据需求 | 推荐 MCP | 并行优先级 |
|---|---|---|
| 法条 / 法规现行性 | 北大法宝 / 威科 / 元典 | 必并行 |
| 类案检索 | 元典 / 聚法 / 法宝 | 高 |
| 司法解释 | 北大法宝 | 高 |
| 工商信息 | 国家企业信用信息公示 | 中 |
| 知识产权 | 国知局 | 中 |
| 案例 / 法规 公开源 | 中国政府网 / 司法部 | 低（兜底）|

**未连接 MCP 时**：明示标注「[待权威数据库核验]」，**不臆测数据**。

### 阶段 5：输出汇总

最终输出含：
1. **案镜分诊报告**（事实 + 关系 + 复杂度）
2. **理镜推理报告**（主线 + 反方 + 强度）
3. **法镜效力报告**（所有引用法条 + 配套 + 时效）
4. **plugin 输出**（实务工作产物）
5. **综合建议**（下一步行动清单）

## 编排模板详解

### 模板 1：合同审阅

```
案镜 (事实 + 合同关系识别)
    ↓
法镜 (合同法 / 民法典合同编 现行有效核验)
    ↓
理镜 (合同效力 + 违约责任推理)
    ↓
commercial-legal plugin (合同实务审阅)
    ↓
输出：合同审阅意见 + 修改建议 + 风险提示
```

### 模板 2：诉讼策略

```
案镜 (事实 + 诉因识别 + 复杂度)
    ↓
法镜 (诉讼时效 + 程序法核验)
    ↓
理镜 (诉因 + 请求权基础推理)
    ↓
litigation-legal plugin (诉讼策略 + 文书起草)
    ↓
输出：诉讼策略方案 + 起诉状 / 答辩状 + 证据清单
```

### 模板 3：合规审查

```
案镜 (业务事实 + 数据流识别)
    ↓
法镜 (PIPL / 数据安全法 / 行业规范 核验)
    ↓
privacy-legal / regulatory-legal plugin (合规审计)
    ↓
输出：合规评估报告 + 整改建议 + 持续监控方案
```

### 模板 4：劳动争议

```
案镜 (劳动关系事实 + 争议焦点)
    ↓
法镜 (劳动合同法 + 司法解释 核验)
    ↓
理镜 (违法解除 / 工伤认定推理)
    ↓
employment-legal plugin (实务处理)
    ↓
输出：法律意见 + 仲裁 / 诉讼策略 + 计算明细
```

### 模板 5：公司治理

```
案镜 (股权 / 治理结构事实)
    ↓
法镜 (公司法 + 三会制度 + 司法解释)
    ↓
corporate-legal plugin (治理方案)
    ↓
输出：治理建议 + 决议草案 + 风险提示
```

### 模板 6-10：知识产权 / AI 合规 / 刑事 / 产品 / 法务咨询

（详见各 plugin 的 SKILL.md,本编排器按需调用）

## 专家协同（复杂案件）

当复杂度 ≥ 4.5 时,触发专家协同：

| 专家 | 角色 | 调用条件 |
|---|---|---|
| 民事律师 | 主审 | 涉及民事案件 |
| 商事律师 | 合规 / 合同 | 涉及商业交易 |
| 知产律师 | IP 案件 | 涉及商标 / 专利 / 著作权 |
| 刑事律师 | 刑事案件 | 涉及刑事辩护 |
| 合规顾问 | 合规审计 | PIPL / 数据 / 反垄断 |
| 税务师 | 涉税案件 | 涉税要素 |

⚠️ **专家协同 = 多个 skill / plugin 的并行调用**,不是单独的"专家 skill"。

## 质量自检清单（编排完成前）

- [ ] 任务意图识别正确,模板选择合理
- [ ] 案镜分诊报告**先于**所有后续步骤
- [ ] plugin 调度按需,未"全套调用"
- [ ] MCP 数据流按并行优先级排序
- [ ] 综合输出**所有 4 个组件齐全**
- [ ] 下一步行动清单**有截止日 / 责任人**
- [ ] 时效管理已标注

## 与其他镜鉴 skill 的关系

| 镜 | 关系 |
|---|---|
| `案镜` (anmirror) | 强制前置 |
| `理镜` (limirror) | 必经 |
| `法镜` (famirror) | 并行 / 必经 |
| `鉴枢` (本) | 编排层 |

## 与上游 plugin 的关系

`鉴枢` **优先调用**镜鉴 suite 的结构化输出（anmirror/limirror/famirror）作为事实地基与推理骨架,
**然后**调用 CSlawyer1985 plugin 做实务工作。
**不直接跳过**镜鉴 suite 直接调 plugin —— 否则失去结构化基础。
