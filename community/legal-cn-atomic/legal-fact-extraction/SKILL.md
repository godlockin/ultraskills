# 法律事实要素提取 (legal-fact-extraction)

> 法学方法论基础 skill：所有后续推理、判断、检索、文书都依赖准确的事实提取。

## 何时触发

- 用户给一段文字描述（含起诉状、答辩状、聊天记录、新闻、合同条款等），要求"梳理"、"提取"、"分析"事实要素
- 准备进入法律推理或文书起草前的「事实地基」构建
- 审查已写法律文书时核对事实一致性
- 类案检索前需要把案件事实标准化

## 何时不触发

- 纯法理讨论 / 概念解释（用 `legal-concept-clarification`）
- 已有结构化事实清单（直接处理，不重复提取）
- 仅需检索法条 / 案例（用上游 `external/claude-for-legal-ZH/plugins/...` 或 `legal-article-retrieval`）

## 工作流：5 步法

### 步骤 1：当事人识别

识别**所有**参与法律关系的当事人，按主体类型分类：

| 主体类型 | 识别要点 | 输出格式 |
|---|---|---|
| 自然人 | 姓名 / 化名 / 角色（如"原告"、"被告"、"第三人"）| `姓名（角色）：身份信息如有` |
| 法人 | 全称 / 简称 / 统一社会信用代码（如有）| `法人全称（角色）：统一社会信用代码如有` |
| 非法人组织 | 个体工商户 / 合伙企业 / 其他 | 同上 |
| 不特定主体 | 涉及公众利益、监管机构 | `主体类型 + 角色` |

⚠️ 注意：聊天记录 / 口头协议中常用"我"、"他"、"对方"等代词 — 必须**还原为具体主体**或标注「主体不明」。

### 步骤 2：行为 / 事件时间线

按**时间先后**列出所有具有法律意义的行为或事件：

```
[timestamp/date] 行为主体 → 行为对象 + 行为内容 + 行为结果（如有）
```

识别要点：
- 行为类型：作为 / 不作为 / 意思表示 / 事实行为
- 行为时点：合同签订日、违约日、侵权日、通知到达日、付款日
- 行为地点（涉及管辖）
- 行为方式（书面 / 口头 / 电子数据 / 默示）

⚠️ **关键**：未注明日期的行为 = 推定为「时间不明」，**不可虚构日期**。

### 步骤 3：标的 / 客体识别

识别法律关系涉及的**标的物**：

| 标的类型 | 识别要点 |
|---|---|
| 财产权益 | 金钱 / 物 / 知识产权 / 股权 / 债权 |
| 人身权益 | 生命 / 健康 / 姓名 / 名誉 / 隐私 |
| 行为义务 | 作为义务 / 不作为义务 |
| 智力成果 | 作品 / 专利 / 商标 / 商业秘密 |

### 步骤 4：法律关系初判

基于上述三步，**初步判断**可能涉及的法律关系：

| 法律关系类型 | 识别信号词 |
|---|---|
| 合同关系 | 合同 / 协议 / 约定 / 承诺 / 履行 / 违约 |
| 侵权关系 | 损害 / 过错 / 因果关系 / 赔偿 |
| 不当得利 | 无因 / 受益 / 损失 / 返还 |
| 无因管理 | 管理他人事务 / 防止损害 |
| 婚姻家庭 | 婚姻 / 继承 / 抚养 / 赡养 |
| 劳动争议 | 用工 / 工资 / 解除 / 工伤 |
| 公司治理 | 股东 / 决议 / 增资 / 减资 / 清算 |
| 行政法律关系 | 行政许可 / 处罚 / 强制 / 复议 |
| 刑事法律关系 | 犯罪构成 / 正当防卫 / 共同犯罪 |

⚠️ 同一案件可能涉及多种法律关系，必须**全部列出**。

### 步骤 5：缺口标记 + 进一步取证建议

对每一步提取结果，**显式标记证据缺口**：

```
证据缺口类型：
- [事实空白] 关键事实未在材料中体现
- [证据缺失] 事实存在但缺书面证据
- [主体不明] 当事人身份待确认
- [时点不清] 关键行为时间不明
- [内容矛盾] 不同来源对同一事实描述不一致
```

## 输出模板

```yaml
案件事实要素清单:
  当事人:
    - 主体: [姓名/名称]
      角色: [原告/被告/第三人/...]
      身份信息: [如有]
    - ...
  
  时间线:
    - 时间: [YYYY-MM-DD 或 "时间不明"]
      主体: [行为人]
      行为: [行为简述]
      证据: [如有]
    - ...
  
  标的:
    - 类型: [财产权益/...]
      内容: [标的描述]
      价值: [如有]
    - ...
  
  可能法律关系:
    - [合同关系 / 侵权关系 / ...]
    - ...
  
  证据缺口:
    - [事实空白/证据缺失/...] [具体描述]
    - ...
```

## 质量自检清单（输出前必走）

- [ ] 所有代词（「我」「他」「对方」）已还原为具体主体或标注「主体不明」
- [ ] 所有时间点有明确日期或标注「时间不明」，**不虚构**
- [ ] 法律关系初判覆盖所有可能类型（不仅是最显眼的那个）
- [ ] 证据缺口显式列出（而非隐含）
- [ ] 标的识别区分了主标的和从标的

## 与其他 skill 的衔接

| 下游 skill | 本 skill 输出的用途 |
|---|---|
| `legal-concept-clarification` | 标的法律关系中的核心法律概念需要解释时 |
| `syllogistic-reasoning` | 时间线 + 法律关系 → 大前提/小前提/结论推理 |
| `norm-validity-check` | 涉及的具体法条需要验证现行有效性 |
| `argument-chain-construction` | 证据缺口 → 补强证据 → 论证链 |
| 上游 plugin `commercial-legal` 等 | 事实清单 → 商业场景的法律服务 |
