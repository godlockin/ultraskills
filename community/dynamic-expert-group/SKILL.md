# 动态专家组技能

## 概述

本技能用于动态组建专家组，对复杂任务进行多角度分析、讨论和决策。

## 核心工作流

```
用户输入 → 默认专家分析 → 识别任务类型 → 匹配领域专家 → 组建专家组 →
并行分析 → 汇总讨论 → 投票决策 → 执行交付
```

## 使用流程

### 1. 任务分析

如果用户输入是模糊的一句话：
1. 使用提问的方式细化任务
2. 识别任务类型、复杂度、涉及领域
3. 确定需要的专家数量和类型

如果用户输入已足够清晰：
1. 直接分析任务特征
2. 匹配相关关键词
3. 搜索专家库

### 2. 搜索专家

使用 `scripts/search_experts.py` 搜索匹配专家：
```bash
python scripts/search_experts.py "<任务描述>"
```

或者直接在 `references/task_patterns.md` 中查找任务类型对应的专家组合。

### 3. 组建专家组

**标准配置**：

| 任务复杂度 | 专家组构成 |
|------------|------------|
| L1 简单 | 默认分析师 + 1领域专家 |
| L2 中等 | 默认分析师 + 2领域专家 + 项目管理 |
| L3 复杂 | 默认分析师 + 2资深专家 + 项目管理 |
| L4 战略 | 默认分析师 + 2资深专家 + 战略顾问 + 教练 |

**必须包含**：
- 默认分析师/HR（任务分析、进度协调）
- 至少1位领域专家

**可选**：
- 项目管理（复杂任务）
- 战略顾问（决策类）
- 教练（团队相关）

### 4. 专家并行分析 (Map)

每个领域专家独立分析任务：
- 阅读任务背景
- 从本专业角度分析
- 提出方案或建议
- 评估风险和机会

**输出格式**：
```markdown
## [专家名称] 的分析

### 视角
[从专业角度看到的任务特征]

### 建议
[具体建议或方案]

### 风险
[可能的风险点]

### 置信度
[建议的确定性：High/Medium/Low]
```

### 5. 讨论与投票 (Reduce)

1. **汇总各专家观点**：整理成统一格式
2. **讨论**：识别分歧点，尝试调和
3. **投票**：每个专家对方案进行投票
4. **决策**：
   - 多数同意 → 执行
   - 僵局 → 组长（默认分析师）打断，按最优方案预演
   - 重新讨论 → 最多3轮

### 6. 执行交付

根据决策结果执行任务，产出最终交付物。

## 专家属性模型

每个专家包含：
- **基本信息**：id, name, name_cn, domain, level, avatar
- **性格特征**：personality_type, traits, communication_style
- **背景**：education, experience, background_story
- **思维框架**：thinking_framework
- **决策风格**：decision_style, risk_tolerance
- **工作方式**：work_style, input_format, output_format
- **适应场景**：best_for, avoid, trigger_keywords

## 持久化

### 生成的专家

执行任务过程中动态生成的专家，保存到：
```
references/experts/generated/<领域>/
```

文件格式：`<expert_id>.md`

### 讨论记录

保存到临时文件夹：
```
/tmp/dynamic-expert-group/<task_id>/
├── team.json          # 专家组配置
├── analyses/          # 各专家分析
├── discussion.md      # 讨论记录
└── decision.md        # 最终决策
```

### 关键讨论点

精简输出，只保存：
- 关键分歧点
- 决策理由
- 风险提示

## 协作规则

### 并行分析
- 每个专家独立分析，不相互影响
- 使用 subagent 或 Task tool 并行执行

### 投票机制
- 投票阈值：多数同意（>50%）
- 最多3轮讨论+投票
- 僵局时组长决策

### 组长职责
- 协调讨论进程
- 打断过长争论
- 在僵局时做出最终决定

## 示例场景

### 场景1：开发新功能

**输入**："我们需要开发一个用户推荐系统"

**流程**：
1. 分析任务 → 技术开发类，L3复杂度
2. 搜索专家 → 陈架构、产品赵、老码
3. 组团 → 默认分析师 + 架构师 + 产品经理 + 代码审查
4. 并行分析：架构可行性、产品价值、代码质量
5. 讨论 → 确定技术方案和产品优先级
6. 投票 → 通过
7. 交付 → 技术方案 + 开发计划

### 场景2：品牌营销活动

**输入**："我们要做一个新品发布活动"

**流程**：
1. 分析任务 → 营销类，L2复杂度
2. 搜索专家 → 营销吴、内容孙、社交郑
3. 组团 → 营销专家 + 内容策略 + 社交运营
4. 并行分析：营销策略、内容创意、传播方案
5. 讨论 → 整合成完整方案
6. 投票 → 通过
7. 交付 → 营销方案 + 执行计划

## 扩展专家库

### 添加新专家

1. 创建 `references/experts/<domain>/<expert_id>.md`
2. 使用 `assets/templates/expert_template.md` 格式
3. 运行 `scripts/init_expert_lib.py` 重建索引

### 动态生成专家

在任务执行中生成的专家：
1. 创建 markdown 文件
2. 包含完整专家属性
3. 保存到 `references/experts/generated/`
4. 下次搜索时可被匹配
