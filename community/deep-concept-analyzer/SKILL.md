# 🔍 深度概念解析器 (Deep Concept Analyzer)

> **"任何概念，拆到十个维度就不再模糊。"**
>
> 基于本体论（Ontology）、系统思考（Systems Thinking）和知识工程（Knowledge Engineering），
> 将用户提出的任意概念、技术、现象或事物，拆解为全面、立体、高逻辑性的结构化知识体系。

---

## 📌 何时该用本 skill

| 触发场景 | 典型例句 |
|---|---|
| **学习新概念** | "帮我分析一下量子计算" / "新能源汽车到底是什么" |
| **深度理解** | "容器化和虚拟机的本质区别是什么" / "搞懂 Transformer 架构" |
| **写科普/备课** | "帮我把认知偏差讲清楚，要能教给别人" |
| **建立知识体系** | "帮我梳理一下密码学的知识结构" |
| **对比辨析** | "微服务和单体架构对比分析" |
| **快速扫盲** | "5 分钟搞懂区块链" |
| **小白科普** | "用小学生能听懂的话解释机器学习" |

**不适用**：简单名词解释（直接回答）、纯主观评价（→ `generalist-expert`）、商业决策分析（→ `strategy-consulting-framework`）、深度调研报告（→ `hv-analysis`）。

## 🧠 核心信念

1. **无知源于维度缺失** — 模糊理解 = 关键维度未覆盖。十个维度全拆完，概念自然清晰。
2. **结构 > 堆砌** — 信息罗列无用，有机结构才有理解。静态本体 → 系统关系 → 动态时空，三层递进。
3. **类比是第一教学法** — 抽象概念必须落地到已知经验。每个维度都有"像什么"的锚点。
4. **元认知是终局** — 不只讲"是什么"，更要给"怎么想"和"下一步问什么"。

## 🧩 十维知识理解框架（速查）

> 完整方法论 → `references/ten-dimensions-framework.md`
> 不要在主流程展开十个维度的详细解释。

| # | 维度 | 核心问题 | 所属层 |
|---|---|---|---|
| 1 | **名称和概念** | 它叫什么？名字从哪来？ | 静态本体 |
| 2 | **类别和种属** | 它在知识树上的哪个位置？ | 静态本体 |
| 3 | **含义和定义** | 一句话说清本质（种差+属） | 静态本体 |
| 4 | **特征和属性** | 区别于同类事物的关键印记 | 静态本体 |
| 5 | **组成和结构** | 内部怎么构成？各部分怎么交互？ | 静态本体 |
| 6 | **作用与功能** | 解决什么痛点？输出什么价值？ | 系统关系 |
| 7 | **条件与环境** | 什么条件下生效？有什么边界约束？ | 系统关系 |
| 8 | **历程与演变** | 从哪来？经历了哪些关键转折？ | 动态时空 |
| 9 | **前景与趋势** | 未来 3-5 年往哪走？ | 动态时空 |
| 10 | **风险与挑战** | 有什么瓶颈、副作用、伦理问题？ | 动态时空 |

**三层递进逻辑**：

```
维度 1-5 → 静态本体（它是什么）
    ↓
维度 6-7 → 系统关系（它怎么用 / 什么环境）
    ↓
维度 8-10 → 动态时空（它从哪来，去向何方）
```

## 🚀 主流程 — 标准十维解析

> **默认模式**。用户说"分析 XX" / "深度拆解 XX" 时走此流程。
> 10 个维度逐一填充，缺信息就标注 `[待补充]`，不编造。

### Step 0 · 概念接收与预判

**目标**：识别概念，判断领域归属。

**动作**：
- 确认概念名称（含别称、缩写）
- 判断所属领域（科技 / 商业 / 哲学 / 医学 / 社会科学 / 艺术 / 其他）
- 判断复杂度，决定展开深度：
  - **简单概念**（如"API"、"缓存"）：每个维度 1-3 条要点
  - **复杂概念**（如"量子计算"、"康德哲学"）：每个维度 3-5 条要点 + 类比 + 图示

**输出**：领域标签 + 复杂度级别

### Step 1-5 · 静态本体层

**目标**：回答"它是什么"。

按维度 1→5 顺序填充，每维度必出物：
- **维度 1**：标准名称 + 别称/英文/代号 + 词源背景
- **维度 2**：上级属概念 + 平级并列概念 + 下级子概念（用缩进树或表格）
- **维度 3**：一句话本质定义（种差 + 属，≤50 字）
- **维度 4**：3-5 个区别于同类概念的核心特征
- **维度 5**：组成部分 + 关联关系（用 ASCII 图或 Mermaid 如果适合）

**工具**：`templates/static-ontology.md`

### Step 6-7 · 系统关系层

**目标**：回答"它怎么用 / 什么环境"。

- **维度 6**：核心价值 + 典型应用场景 + 目标受众
- **维度 7**：前提条件 + 环境约束 + 边界条件 + 依赖项

**工具**：`templates/system-relations.md`

### Step 8-10 · 动态时空层

**目标**：回答"它从哪来，去向何方"。

- **维度 8**：时间线（起源 → 关键里程碑 → 当前阶段），用表格呈现
- **维度 9**：3-5 年趋势预测，保持中立客观
- **维度 10**：技术瓶颈 + 伦理风险 + 商业挑战 + 替代威胁

**工具**：`templates/dynamic-spacetime.md`

### Step Final · 元认知总结

**目标**：给用户"一句话带走"和"继续思考的起点"。

**必出物**：
- 💡 **认知卡片小结**：一句话提炼（≤30 字）
- ❓ **3 个延伸思考**：基于该概念的深度提问

**工具**：`templates/metacognition-closure.md`

## ⚡ 交互模式（快捷指令）

> 用户在输入概念时附加指令，自动切换输出模式。

### /quick [概念] — 速读模式

**触发**：`/quick 区块链` / "快速说一下XX" / "30 秒搞懂XX"

**输出**：仅保留 4 个核心维度，≤300 字极简卡片：
- 维度 3：一句话定义
- 维度 5：组成结构
- 维度 6：作用功能
- 维度 10：风险挑战

**模板**：`templates/quick-mode.md`

### /compare [概念A] VS [概念B] — 对比模式

**触发**：`/compare 微服务 VS 单体架构` / "XX 和 YY 有什么区别" / "对比一下XX和YY"

**输出**：将 10 个维度转换为对比表格，逐行对比两个概念。

**特殊处理**：
- 相同维度用 ✅ 标记一致
- 关键差异用 🔴 标记
- 底部给出"选 A 不选 B"的决策条件

**模板**：`templates/compare-mode.md`

### /eli5 [概念] — 小白模式

**触发**：`/eli5 机器学习` / "用小学生能听懂的话解释XX" / "给不懂技术的人讲XX"

**输出**：保持 10 个维度逻辑，但每个维度用通俗比喻、故事或生活常识解释，去掉专业术语。

**原则**：
- 每个维度锚定一个日常生活场景
- 专业术语必须翻译成大白话（括号标注原词）
- 多用"就像..."、"好比..."开头

**模板**：`templates/eli5-mode.md`

### /mindmap [概念] — 脑图模式

**触发**：`/mindmap 系统论` / "帮我画个XX的思维导图" / "XX的知识图谱"

**输出**：以 Mermaid mindmap 代码块输出 10 个维度的思维导图源码。

**模板**：`templates/mindmap-mode.md`

## 🚨 必守规则

| # | Rule | 违反即停 |
|---|---|---|
| R1 | **不编造事实** — 不确定的信息标注 `[待补充]`，不给错误答案 | ✋ |
| R2 | **定义必须种差+属** — 维度 3 一句话定义必须包含"区别于同类事物的特征"+"所属上位概念" | ✋ |
| R3 | **十维尽量覆盖，但允许逃生阀** — 维度信息不足时必须标注 `[该维度暂无足够公开信息]`；若客观证据无法支撑任何维度，输出"信息不足以做严肃拆解"并停止本流程，而不是硬凑 | ✋ |
| R4 | **类比不扭曲原意** — 通俗化可以，但不能用错误类比误导 |
| R5 | **前景中立** — 不夸大、不贬低，争议性问题标注"存在不同观点" | ✋ |
| R6 | **来源具体可追溯** — 关键事实/数据必须给具体出处（作者、年份、刊物 / 文档链接 / 报告名），仅写"学术论文"等类型不够 | ✋ |
| R7 | **不替代专业建议 + 不替代过程性 how-to** — 医学/法律/投资概念解析结尾必须加免责声明；当用户问的是「如何做 X」而非「X 是什么」时，转 `process-doc` / `how-to` 类专项 skill，本 skill 只解析概念 | ✋ |

## 🚨 Anti-Patterns · 红线

| ❌ 反模式 | 为什么坏 | 修正 |
|---|---|---|
| **维度跳跃** | 跳维度 = 漏关键视角 | 严格 1→10 顺序 |
| **维度过简** | "它很有用" = 没说 | 每维度至少 1 个具体事实 |
| **类比不当** | "区块链就是 Excel 共享" 过度简化 | 类比 + 标注简化了什么 |
| **编造数据** | "市场规模约 500 亿" 无来源 | 标注 `[待补充]` |
| **堆砌术语** | 用更难的词解释难词 | 每术语必附白话解释 |
| **忽略风险** | 只讲好处不讲坑 | 维度 10 必覆盖 |
| **混用模式** | `/quick` 里讲 10 个维度 | 按模式裁剪 |

## 🛠 自检 Checklist（每次输出前）

- [ ] 10 个维度全部覆盖？（缺维度已标注 `[待补充]`）
- [ ] 维度 3 定义是"种差+属"结构？（≤50 字）
- [ ] 维度 5 结构描述清晰？（读者能画出框图）
- [ ] 维度 8 时间线有具体年份/阶段？
- [ ] 维度 10 风险和挑战非空？
- [ ] 类比准确不扭曲原意？
- [ ] 元认知总结完成？（认知卡片 + 3 个延伸思考）
- [ ] 模式匹配正确？（/quick 只出 4 维 / /compare 出对比表）
- [ ] 无编造数据？关键事实有来源标注？
- [ ] 需要免责声明的领域已加？（医学/法律/投资）

---

> **核心心法**：十个维度像十面镜子 — 每一面都从一个独特角度照出概念的本质。缺一面，理解就缺一角。
