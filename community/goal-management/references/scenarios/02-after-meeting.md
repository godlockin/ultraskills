# 场景 02 · 经营/工作会议后拆目标

## 触发

- 刚开完季度/年度经营会议
- 公司/部门定了 OKR
- 你需要把它拆到自己的执行计划

---

## 5 步流程

### Step 1 · 会议纪要立刻整理

**会议结束后 1 小时内**,把会议要点写成纪要:

```markdown
## [会议名] 纪要 · [日期]

### 关键决策
1. [决策 1]
2. [决策 2]

### 分配到我的目标
1. [目标 1]:[量化指标]
2. [目标 2]:[量化指标]

### 不清楚的点
1. [疑问 1]
2. [疑问 2]

### 下一步
- [ ] 追问 [谁] 关于 [问题]
- [ ] [日期] 前提交 [方案]
```

**为什么**:
- 别人也会写纪要 — 你的版本一定要先发出去(R4)
- 不清楚的点必须显化 — 防止会议后没人认领

---

### Step 2 · 24h 内书面确认

发给关键人(领导/会议主席):

> "会议纪要如附件,请确认是否有遗漏或理解偏差。"

**24 小时未回复视为默认同意**(潜规则,但要邮件留痕)。

---

### Step 3 · OKR 拆解到自己的执行层

**模板**:

```
公司/部门 OKR
  O: [战略目标]
  KR1: [上层指标]

我的 OKR(对齐上层):
  O: [我的承接方向,加 30% 自有特色]
  KR1: [量化指标,从上层拆解]
  KR2: [个人/团队指标]
  KR3: [创新/突破指标]

我的 Initiatives:
  KR1 → 动作 A / B
  KR2 → 动作 C
  KR3 → 动作 D
```

**70/30 原则**:
- 70% 服务上层 OKR
- 30% 自有(避免完全被动)

---

### Step 4 · 时间分配(季度/月度/周度)

```
Q[X]:
├─ M1:
│   ├─ W1: [动作]
│   ├─ W2: [动作]
│   ├─ W3: [动作]
│   └─ W4: [动作] + M1 复盘
├─ M2:
│   └─ ...
└─ M3:
    ├─ ...
    └─ Q[X] 总结 + Q[X+1] 规划
```

**关键**:
- 关键里程碑必须落在月初(不要拖到最后一周)
- 每周留 1 天 buffer
- 月末留 1 天做月复盘

---

### Step 5 · 风险与依赖关系识别

**风险清单**:
| 风险 | 影响 | 概率 | 预案 |
|---|---|---|---|
| 依赖 [X 部门] 输出 | 不能完成 KR1 | 中 | 周三催一次 + 备用方案 |
| 关键人员请假 | 进度延后 3 天 | 低 | 提前培养 backup |
| 预算未批 | 不能执行 | 中 | 周一就提交预算申请 |

**依赖关系图**:
```
我的 KR1
├─ 依赖: [X 部门] 输出(他们 M2 第 1 周给)
├─ 依赖: 预算审批(本周)
└─ 依赖: [Y 同事] 配合(下周一定)
```

---

## 输出范式

```markdown
## [周期] OKR 拆解 · [主公] · 基于 [会议名]

### 上层 OKR(承接)
[复制会议上的公司/部门 OKR]

### 我的 OKR
O: ...
KR1: [量化] 从 X → Y,截止 [日期]
KR2: [量化] 从 X → Y,截止 [日期]
KR3: [量化] 从 X → Y,截止 [日期]

### 70/30 对齐
- 70% 服务上层:KR1/KR2
- 30% 自有:KR3

### 时间分配(季度 → 月度 → 周度)
[甘特图或表格]

### 依赖与风险
- 依赖: ...
- 风险 1: ... + 预案
- 风险 2: ... + 预案

### Initiative(主动动作)
[每个 KR 对应的具体动作清单]

### 资源需求
- 人: ...
- 钱: ...
- 协作: ...
```

---

## 反模式

| ❌ 反模式 | 为什么坏 | 修正 |
|---|---|---|
| 会议后没纪要 | 别人版本不一致 | 1h 内发纪要 |
| OKR 100% 服务上层 | 失去主动权 | 70/30 原则 |
| KR 太多 | 失焦 | 最多 5 个 KR |
| 没时间分配 | 季度变年底冲 | 月/周/日 拆解 |
| 风险没预案 | 出问题就慌 | 每个 KR 1 个风险预案 |
