# 前置情境智慧 · 4 项信息补齐协议

## 为什么需要这 4 项?

**主公提示词原话**:
> 在开始目标管理之前,要先帮我补齐这些信息 — 了解组织的战略目标、了解领导的管理风格和特点、了解我自己的优势和劣势、了解同事的组成以及他们之间的人际关系。

**本质**: 任何目标管理方案,如果不基于这 4 项情境,就是**凭空猜测**,方案很可能是错的。

---

## 4 项详解

### ① 组织战略目标

**要回答的问题**:
- 公司/部门未来 1 年的战略目标是什么?
- 核心 OKR 是什么?
- 战略优先级如何?增长?盈利?市场份额?
- 我们在战略中的位置?主力部门?辅助部门?

**信息源**:
- 公司年度战略文件(全员工公开)
- 部门 OKR 文档
- 季度全员会议
- 老板邮件/讲话

**主公输入范式**:
> "我们公司今年战略是 [增长],核心 OKR 是 [Q1 新客 10k,Q2 留存 80%]。"

---

### ② 领导管理风格

**要回答的问题**:
- 领导是数据驱动还是关系驱动?
- 领导喜欢书面还是口头汇报?
- 领导风格偏放权还是偏控制?
- 领导对失败的容忍度?
- 领导最不喜欢下属做什么?

**信息源**:
- 历史合作经验
- 同事反馈
- 领导过往邮件/讲话风格
- 行业知识(领导是哪一代管理者?)

**主公输入范式**:
> "我老板是 [数据驱动 + 喜欢书面 + 偏放权 + 失败容忍度中等 + 最不喜欢下属不汇报]。"

**简化版(主公不愿详细描述时)**:
> "我老板管得细,喜欢书面,失败 1 次可接受。"

---

### ③ 主公个人优劣

**要回答的问题**:
- 强项:目标拆解?谈判?执行?创新?
- 弱项:跨部门协作?公开演讲?数据敏感?
- 历史成功模式:什么场景下做得好?
- 历史失败模式:什么场景下反复卡?

**信息源**:
- 主公自评
- 月度目标管理学习报告(自动沉淀)
- 同事反馈
- 历史绩效

**主公输入范式**:
> "我强项是 [目标拆解 + 数字敏感],弱项是 [跨部门谈判 + 公开演讲]。"

**自动沉淀机制**:
- 每月月度报告自动更新画像
- 主公不必每次重复

---

### ④ 同事关系 + 部门政治

**要回答的问题**:
- 关键同事是谁?
- 谁是盟友?谁是中立?谁是潜在风险?
- 部门间是否有历史恩怨?
- 谁最可能甩活?谁最可能帮忙?
- 哪些决定需要谁点头?

**信息源**:
- 主公自身经验
- 同事饭桌/私下交流
- 组织结构图
- 历史协作记录

**主公输入范式**:
> "同事:张三盟友,李四中立,王五是竞争关系(可能抢资源)。跨部门:市场部领导和我老板关系一般。"

---

## 信息收集协议

### 首次使用(详细模式)

我(目标管理 skill)会主动问:

```
1. 你的公司/部门今年战略目标是什么?核心 OKR 是?
2. 你的直接领导是什么管理风格?(1-2 句话)
3. 你自己的优势和劣势?(1-2 句话)
4. 你身边的同事/部门关系有什么要特别注意的?(1-2 句话)
```

**主公可以**:
- 完整回答(我出方案更精准)
- 部分回答 + 跳过(我用合理假设)
- 全部跳过(我标"假设前提"出方案)

### 后续使用(自动读取模式)

主公不必重复 — 我会从以下来源自动读取:
- 月度目标管理学习报告(主公画像)
- 历史对话沉淀
- 主公主动更新的画像

**主公可主动更新画像**:
> "我刚发现我最大的弱项是 [X],请更新到我的画像。"

### 跳过兜底模式

主公说"跳过情境"时:

**我会**:
1. 用**行业默认假设**(中型企业 + 传统管理层 + 个人执行者)
2. 明确标注"假设前提",提醒主公根据实际调整
3. 提示"补齐情境可提升方案精准度 50%+"

## 输出范式

### 主公画像文档(自动维护)

```yaml
主公画像:
  组织战略:
    - 行业: [SaaS / 电商 / ...]
    - 战略主题: [增长 / 盈利 / 转型]
    - 核心 OKR: [O1, O2, O3]
    - 战略优先级: [P0: ... / P1: ...]

  领导风格:
    数据驱动: [高/中/低]
    书面偏好: [高/中/低]
    放权程度: [高/中/低]
    失败容忍: [高/中/低]
    最忌讳: [不汇报 / 不留痕 / ...]

  主公风格:
    强项: [目标拆解 / 数字敏感 / 谈判 / ...]
    弱项: [跨部门 / 公开演讲 / ...]
    成功模式: [场景 A + 动作 X = 成功]
    失败模式: [场景 B + 动作 Y = 失败]

  同事关系:
    盟友: [张三 + 李四]
    中立: [王五]
    风险: [赵六(可能抢资源)]
    跨部门关键人: [市场部 X + 财务部 Y]
```

### 方案中显化情境

每次出方案,头部要写:

```
## 方案前提(基于主公画像)

- 组织: [战略主题 + 核心 OKR]
- 领导: [管理风格摘要]
- 主公: [强项 + 弱项]
- 同事: [关键关系]

未补齐项: [2 项] — 方案用合理假设
```

---

## 隐私与数据边界

- 主公画像**仅本 skill 内部使用**
- 不外发,不展示给第三方
- 主公可随时要求"念出你对我画像的全部内容"
- 主公可随时要求"删除画像中的某项"

---

## 与月度报告的双向迭代

```
首次 → 详细收集 4 项
        ↓
后续对话 → 自动读取画像
        ↓
每月报告 → 画像迭代
        ↓
下次对话 → 用最新画像
```

**画像** = 主公的"数字孪生",越用越准。
