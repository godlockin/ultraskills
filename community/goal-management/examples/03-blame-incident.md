# Example 03 · 差点背锅案例

## 情境

```
事件:某关键客户 Y 投诉响应慢,投诉到总经理
我(主公):销售负责人
差点背锅:销售助理跟进 Y 客户,但没及时响应
结果:客户差点流失
```

---

## 完整事件时间线

```
07-15  客户 Y 发邮件询问技术问题
07-15  销售助理小王收到,转给技术部
07-16  技术部没回复(小王没催)
07-17  客户 Y 第二次催促(电话销售助理)
07-17  销售助理回复"已催技术"(实际没催)
07-18  技术部回复,但客户 Y 不满意
07-19  客户 Y 投诉到总经理
07-19  总经理找我:"Y 客户为什么投诉?"
```

---

## 我当时怎么处理的(应急)

### 1. 不要慌

```
1. 立即联系客户 Y — 道歉 + 解决方案
2. 内部调查 — 找小王 + 技术部沟通
3. 给总经理完整时间线 + 我的改进方案
```

### 2. 应急动作

```markdown
致客户 Y 邮件:
"非常抱歉响应延迟。已查明 [根因],立即采取以下措施:
1. [今天] 前给您完整答复
2. 我本人接管您的服务,不再经过中间人
3. 补偿 [X 优惠]
期待继续合作。"
```

### 3. 给总经理的邮件

```markdown
主题:客户 Y 投诉事件完整报告 + 改进方案

[完整时间线]
[根因: 销售助理没及时跟进 + 技术部响应慢]
[我本人的责任: 关键客户没亲自管]
[改进方案 3 件]
[已采取的应急动作]
```

### 4. 不甩锅给小王

**关键**:
- 复盘时**不追责**(虽然小王确实有错)
- 重点放在"为什么流程上让这种错误可能发生"
- 改进流程 + 我自己的责任承担

---

## 根因分析(5 Why)

```
问题:Y 客户投诉响应慢
├─ Why 1: 为什么响应慢?—— 技术部没及时回复
├─ Why 2: 为什么技术部没及时回复?—— 小王没催
├─ Why 3: 为什么小王没催?—— 小王不知道 Y 是关键客户
├─ Why 4: 为什么小王不知道?—— 关键客户名单没明确分级
└─ Why 5: 为什么没分级?—— 我没建立"关键客户日报"机制
```

**根因**: 我没建立关键客户管理机制 + 我自己没亲自跟关键客户。

---

## 我的责任承担

```
错误 1: 关键客户没亲自跟,过度依赖助理
错误 2: 没建立关键客户日报机制
错误 3: 没培训助理识别关键客户
```

**改进动作(7 月底前完成)**:
1. [ ] 7-25 关键客户名单我自己跟(不通过助理)
2. [ ] 7-26 建立 VIP 客户日报模板
3. [ ] 7-28 助理培训 1 次(关键客户识别)
4. [ ] 7-30 总经理面前汇报改进方案

---

## 沉淀到知识库

**条目 1 · 规律类**:
> **关键客户必须负责人亲自跟,不经过中间人**。
> 适用:客单价 > 50 万 / 战略级 / 风险敏感 客户
> 不适用:小客户(可授权助理)
> 反例:让助理跟进 Y 客户差点流失

**条目 2 · 陷阱类**:
> **关键客户管理 = 4 件套 + 1 个红线**
> 4 件套:日报 + 周复盘 + 月度 QBR + 季度面对面
> 红线:负责人必须亲自管理,不授权

---

## 我学到的 3 件事

1. **关键客户不能授权** — 必须亲自跟,中间人传递会丢失
2. **助理必须有培训 + 监督** — 不能默认助理知道什么重要
3. **风险前置 > 危机响应** — 早建立机制,避免事后救火
