# Example 02 · 跨部门目标对齐案例

## 情境

```
场景:产品部 + 销售部对不齐
产品 Q3 OKR: 上线 X 新功能
销售 Q3 OKR: 新客 500
冲突: 销售需要 X 功能 demo 给客户,但产品排期 Q4 上线
```

---

## 解决流程

### Step 1 · 准备

**写议程发双方**:

```markdown
## 跨部门对齐会议 · 产品 + 销售 Q3 OKR

### 议程
1. 共同目标回顾 (10min)
2. 当前冲突 (20min) — X 功能上线时间
3. 3 方案权衡 (20min)
4. 资源协调 (10min)
5. 决策与下一步 (10min)

### 我希望拿到
- X 功能 Q3 部分能力上线的承诺
- 双方领导对方案的共识
- 后续跟进机制
```

### Step 2 · 会议开场

> "今天主要是想对齐 Q3 共同目标。我们共同点是 [服务客户],共同挑战是 [X 功能不上线销售 demo 受影响]。我们 70 分钟找出可执行方案。"

### Step 3 · 显化冲突 + ART 三角

```
冲突: X 功能上线时间
  产品 Q4 上线 vs 销售 Q3 需要

3 方案:
  A · 提前上线(动 R:产品加 2 人 + 销售协调 demo 时间)
  B · 部分能力先上(动 T:Q3 先上核心模块,Q4 完整版)
  C · 推迟销售 demo(动 A:销售用现有功能做 demo)
```

### Step 4 · 用 RACI 锁定

| 任务 | R 责任人 | A 最终责任 | C 咨询 | I 知会 |
|---|---|---|---|---|
| X 功能核心模块 | 产品部 张三 | 产品总监 | 销售部 | 双方 VP |
| 销售 demo 准备 | 销售部 李四 | 销售总监 | 产品部 | 双方 VP |
| Q4 完整版 | 产品部 王五 | 产品总监 | 销售部 | 双方 VP |

### Step 5 · 24h 内发纪要

> **关键**: 双方领导都在抄送栏 — 任何一方反悔都有邮件证据。

---

## 关键学习

1. **议程必发**(不靠即兴)
2. **冲突显化**(不藏在话外)
3. **ART 三角**(给 3 方案让对方选)
4. **RACI 锁定**(避免"谁负责"扯皮)
5. **24h 纪要 + 抄送领导**(关键留痕)

---

## 结果

```
方案 B 被选 — Q3 核心模块先上,Q4 完整版
  - 销售 demo 影响:可控
  - 产品压力:核心模块 Q3 上,质量 OK
  - 双方领导同意 + 邮件确认
```
