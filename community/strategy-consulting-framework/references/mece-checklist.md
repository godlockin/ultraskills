# MECE 检查清单 + 失败案例

> MECE = Mutually Exclusive, Collectively Exhaustive。issue tree 第二层拆出来如果不 MECE,后面所有分析都白搭。

## ✅ 通过清单(Stage 2 退出前必过)

```
□ 同一层节点之间 — 不重叠
□ 同一层节点加起来 — 覆盖所有可能
□ 每个叶子节点 — 可独立分析(给一个假设就能验证)
□ issue tree 总节点 — ≤ 9 个
□ 根问题措辞 — ≤ 30 字,动词开头
□ 每层 — 拆解维度一致(不能这一层按时间、那一层按对象)
```

---

## ❌ 常见不 MECE 的拆法

### 1. **按内部职能拆**(最容易犯)

❌ **Revenue issues** → Product / Sales / Marketing / Go-to-Market

为什么错:Marketing 和 Sales 都做"获取新客",**重叠**;Go-to-Market 又被 Marketing 包含,**包含关系**。

✅ **Revenue issues** → Acquisition / Retention / Expansion(MBB 经典三段)

为什么对:获取新客 / 留住老客 / 提高单客价值,任何客户行为只能落在这三段之一。

### 2. **拆解维度不统一**

❌ 根问题"客户为什么流失":
- A:产品质量差 → 服务态度差 → 价格高
- B:30 天流失 → 90 天流失 → 1 年流失

为什么错:A 按"原因"拆,B 按"时间"拆,混在一起不 MECE。

✅ 选择一个维度统一:
- 按原因:产品 / 服务 / 价格 / 外部
- 按时间:首月 / 中期 / 长期

### 3. **遗漏子分支**

❌ "是否进入海外":只列 3 个分支(机会、风险、行动)

为什么错:漏了"战略一致性"维度 — 进入海外如果跟核心业务不契合,等于分散精力。

✅ 至少 4 个维度:机会 / 资源 / 战略一致性 / 风险 + 替代方案

### 4. **拆太深,叶子不可分析**

❌ "营收增长" → 营销 → 投放 → 关键词 → 长尾词 → 5 个长尾词具体名字

为什么错:到第 5 层就不是"叶子"了,而是"具体动作",不可分析性消失。

✅ 每个叶子都应该对应 1 个可验证假设(可以回答"是 / 否 / 多少")。

### 5. **拆解粒度不均**

❌ "增长":A 拆 5 层,B 拆 2 层,C 拆 1 层

为什么错:粒度不均会让 Stage 4 80/20 无法操作(粒度细的部分稀释结论)。

✅ 各分支尽量拆到同深度(2-3 层),且节点数相近。

## 🧪 MECE 自检实战(3 步)

**Step 1 · 反向覆盖测试**

把每个叶子节点假设成具体场景,问「这个场景属于哪个分支」:
- 如果只能落一个 → MECE 通过
- 如果落 2 个 → 有重叠,要重拆
- 如果无落 → 漏分支,要补

**Step 2 · 边界交叉测试**

相邻分支找一个交叉案例:
- 「获得 1 个新客户」算 Acquisition 还是 Expansion?
  - 如果之前没买过 → Acquisition
  - 如果买过 → Expansion
  - 这就是清晰的边界 ✅

**Step 3 · 总和穷尽测试**

列一个场景清单(过去 6 个月发生过的具体事件):
- 每个场景只落一个叶子节点 → MECE 通过
- 有场景落不进 → 漏分支

## 🛠 实战纠错话术

如果用户给的拆解不 MECE:

```
你给的拆法思路是对的,但我担心这样拆有重叠风险。
比如 [举具体场景] 既属于 A 也属于 B,这样 Stage 3 写假设就会模糊。

我建议换个角度 [MECE 替代方案],这样 [3-4 个] 分支相互独立,
我帮你按 [这个新拆法] 重做一次,你看可以吗?
```

不要直接否定用户的拆法 — 用「换角度」+「重做」给他台阶。
