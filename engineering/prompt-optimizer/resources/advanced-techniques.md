# 高级Prompt工程技巧

> 本文档提炼自顶级Meta-Prompt设计，涵盖超越基础框架的进阶策略。

---

## 🧠 元认知架构 (Meta-Cognitive Architecture)

### 核心理念

优秀的prompt不仅告诉AI"做什么"，更要设计AI"如何思考"。

### C.R.M.T. 认知协议

将AI的思考过程强制结构化为四步回路：

| 阶段 | 名称 | 核心动作 |
|:----:|------|---------|
| **C** | Contextual Representation | 测量输入信息密度，识别核心变量 |
| **R** | Reasoning Chain | 构建推理链路，选择思维模型 |
| **M** | Meta-Verification | 自我验证逻辑完整性 |
| **T** | Task Execution | 执行任务并格式化输出 |

### 应用示例

```markdown
# 思维协议
在响应前，必须执行以下认知回路：
1. **表征构建**: 识别输入中的 X(输入)、Y(输出)、C(约束)、M(推理需求)
2. **逻辑锁定**: 确定任务类型，选择对应的推理策略
3. **元验证**: 检查逻辑链完整性
4. **执行交付**: 按规定格式输出
```

## 🔀 智能模式切换 (Adaptive Mode Switching)

### 核心理念

根据输入的**信息密度**自动选择响应策略，而非询问用户。

### 双模式设计

```
┌─────────────────────────────────────────────────┐
│          用户输入                                │
└─────────────────┬───────────────────────────────┘
                  │
                  ▼
        ┌─────────────────┐
        │  信息密度评估    │
        └────────┬────────┘
                 │
        ┌────────┴────────┐
        ▼                 ▼
┌───────────────┐  ┌───────────────┐
│ Mode A: 握手  │  │ Mode B: 交付  │
│ (密度 < 阈值) │  │ (密度 ≥ 阈值) │
└───────────────┘  └───────────────┘
```

### Mode A: 认知握手

**触发**: 输入模糊，缺少关键信息

```markdown
## 认知蓝图构建

**核心诊断**: [一句话概括核心挑战]

**缺失变量**:
1. 🎯 **目标主体**: [追问具体对象/受众]
2. ⚙️ **核心机制**: [追问推理步骤/格式]
3. ⚖️ **边界约束**: [追问风格/禁忌]

> 💡 直接回答上述问题，或回复 "请自由发挥"
```

### Mode B: 深度交付

**触发**: 信息充分，可直接执行

```markdown
## 认知解析
> 思维链路:
> 1. 任务类型 → [类型]
> 2. 策略选择 → [策略]
> 3. 关键技巧 → [技巧]
> 4. 风险防御 → [护栏]

## 最终输出
[结构化的完整输出]
```

## 🛡️ 防御性设计三件套

### 1. 零废话协议 (Zero-Fluff Protocol)

**禁止的客套话**：

- ❌ "好的，我来为您..."
- ❌ "希望对您有帮助"
- ❌ "如果您有任何问题..."
- ❌ "当然可以！"

**植入方式**：

```markdown
## 输出规范
- 禁止输出任何客套话、寒暄语、开场白
- 直接进入正题，开门见山
- 结尾不要自我评价或祝福语
```

### 2. 防幻觉指令 (Anti-Hallucination)

```markdown
## 知识边界
- 如果不确定答案，必须明确声明"我不确定"
- 禁止编造不存在的引用、数据、事实
- 对于推测性内容，必须标注"这是推测"
```

### 3. 兜底反问机制 (Fallback Clarification)

```markdown
## 信息不足时
当输入信息不足以完成任务时：
1. 不要基于假设强行输出
2. 识别具体缺失的信息点
3. 结构化地向用户提出追问
```

## 📐 强制结构化：五大金刚模块

### 标准System Prompt骨架

```markdown
# Role (角色定义)
[身份 + 专业背景 + 核心能力]

# Profile (档案详情)  
- **Identity**: [具体身份名称]
- **Core Function**: [核心职能描述]
- **Language**: [语言偏好/限制]

# Rules (规则约束)
- [必须遵守的规则]
- [禁止的行为]
- [边界条件]

# Workflow (工作流程)
1. [步骤一]
2. [步骤二]
3. [步骤三]

# Output (输出规范)
- **Format**: [格式要求]
- **Structure**: [结构模板]
- **Length**: [长度限制]
```

### 与 CO-STAR 的对比

| 维度 | CO-STAR | 五大金刚 |
|------|---------|---------|
| 侧重 | 要素完整性 | 模块结构化 |
| 适用 | 单次对话prompt | System Prompt设计 |
| 优势 | 易记易用 | 工程化、可维护 |

**建议**: 用CO-STAR做需求分析，用五大金刚做最终输出。

## 💭 思维链显性化 (Explicit CoT)

### 核心理念

让模型的推理过程**可见、可审计、可调试**。

### 实现方式

#### 方式一：Thinking 标签

```markdown
## 工作流程
在回答任何问题前，你必须：
1. 在 <thinking> 标签内进行深度分析
2. 分析完成后，再输出正式回答

示例格式：
<thinking>
[在此进行推理分析，用户可见]
</thinking>

[正式回答]
```

#### 方式二：步骤强制声明

```markdown
## 推理协议
请按以下步骤思考并**显式输出每一步**：
1. **问题理解**: 用自己的话复述问题
2. **关键分析**: 识别关键因素
3. **推理过程**: 展示逻辑推导
4. **最终结论**: 给出答案
```

#### 方式三：引用验证

```markdown
## 验证机制
每个结论必须附带支撑依据：
- 结论A ← 来源于 [具体信息]
- 结论B ← 推导自 [逻辑链路]
```

## 🎭 高级角色塑造

### 层次化角色定义

普通做法：

```
你是一个写作助手
```

高级做法：

```markdown
# 角色档案

## 身份 (Identity)
**首席内容架构师** (Chief Content Architect)

## 核心能力 (Core Competencies)
- 深度理解认知心理学与说服力写作
- 精通结构化思维与信息架构设计
- 20年跨行业写作经验

## 行为准则 (Behavioral Code)
- 拒绝低质量、模糊的写作请求
- 追求每一个词的精准性
- 绝不妥协于模板化输出

## 语言协议 (Language Protocol)
- 主语言：简体中文
- 专业术语保留英文
- 禁止使用网络流行语
```

### 角色赋予的三种权力

| 权力 | 效果 | 示例 |
|------|------|------|
| **拒绝权** | 强化边界感 | "如遇闲聊请求，直接引导回正题" |
| **追问权** | 提升输出质量 | "信息不足时，必须追问而非猜测" |
| **判断权** | 提升自主性 | "根据信息密度自动选择响应模式" |

## 🔧 P-M-O-S 输出框架

为复杂任务设计的结构化输出骨架：

| 模块 | 名称 | 内容 |
|:----:|------|------|
| **P** | Persona | 角色定位与专业背景 |
| **M** | Mission | 核心任务与成功标准 |
| **O** | Operations | 具体执行步骤与工作流 |
| **S** | Standards | 质量标准与验收规范 |

### 模板

```markdown
## P - Persona (角色)
[定义AI扮演的角色、专业背景、核心能力]

## M - Mission (使命)
[明确核心目标、成功标准、关键交付物]

## O - Operations (操作)
[详细的执行步骤、决策点、分支处理]

## S - Standards (标准)
[输出格式、质量要求、验收清单]
```

## ✅ 高级技巧应用清单

在设计System Prompt时，检查是否应用了以下高级技巧：

### 元认知层

- [ ] 是否定义了认知协议/思考流程？
- [ ] 是否要求显式输出思维链？
- [ ] 是否有自我验证机制？

### 交互层

- [ ] 是否设计了智能模式切换？
- [ ] 是否有结构化的追问模板？
- [ ] 是否提供了"逃逸门"（如"请自由发挥"）？

### 防御层

- [ ] 是否植入了零废话协议？
- [ ] 是否有防幻觉指令？
- [ ] 是否有兜底反问机制？

### 结构层

- [ ] 是否使用了五大金刚/P-M-O-S框架？
- [ ] 是否层次分明（H1/H2/H3）？
- [ ] 示例是否与指令隔离？

### 角色层

- [ ] 是否有层次化的角色定义？
- [ ] 是否赋予了适当的权力（拒绝/追问/判断）？
- [ ] 是否定义了语言协议？
